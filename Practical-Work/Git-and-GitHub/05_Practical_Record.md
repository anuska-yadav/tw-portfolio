# Practical: Version Control Using Git and GitHub

## Aim
To practise version control using Git locally and GitHub as a remote repository.

## Software required
- Git
- GitHub account
- Terminal or VS Code terminal
- Web browser

## Theory
Git is a distributed version control system. It records project history as commits. GitHub hosts Git repositories remotely and supports collaboration through branches, forks and pull requests.

## Important concepts
- Working directory: files currently being edited.
- Staging area: selected changes prepared for a commit.
- Repository: committed project history.
- Commit: saved snapshot with a message.
- Branch: independent line of development.
- Remote: named reference to another repository, commonly `origin`.
- Push: upload local commits.
- Fetch: download remote updates without integrating them.
- Pull: fetch and integrate remote updates.
- Merge: combine histories from branches.

## Procedure
1. Verify Git installation and configure user identity.
2. Initialize or clone a repository.
3. Create files and inspect `git status`.
4. Stage files with `git add`.
5. Save a commit with `git commit`.
6. Inspect history using `git log`.
7. Create a feature branch, commit a change and merge it.
8. Connect a GitHub repository as `origin`.
9. Push commits and practise fetch/pull.
10. Practise undo and conflict resolution in a disposable repository.

## Result
The learner can create and manage a local Git repository, track changes, commit versions, use branches, connect to GitHub and synchronize remote changes.
